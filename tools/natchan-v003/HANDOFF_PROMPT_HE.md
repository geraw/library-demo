# פרומפט מסירה: השלמת קטלוג הטיפוסים והרצת הנתחן על Gitea ו־Vikunja

## המשימה והקשר

אתה ממשיך את עבודת המחקר שלנו על Gitea ועל Vikunja, שבה נוצרו מלכודות ונמצאו ממצאים שנותחו ידנית. כעת עליך להעביר את הידע הזה לנתחן דטרמיניסטי, ולהפעיל אותו על תוצאות הריצה הקיימות באותו מחשב. עליך לבצע את העבודה ולהפיק קבצים, בדיקות ודוחות; תיאור תיאורטי בלבד אינו התוצר המבוקש.

המטרה הראשונה היא לשייך ככל האפשר ממצאים חדשים לטיפוסי בעיות מוכרים, גם כאשר אין לבאג שם או מספר. המטרה השנייה, הנפרדת, היא לשייך ממצא לבאג מסוים שכבר מצאנו כאשר הראיות מספיקות. המטרה השלישית היא להראות התאמה לניתוחים הידניים ההיסטוריים ולחשוף פערים אמיתיים.

הבדל חיוני: מלכודת היא מנגנון הבדיקה; טיפוס בעיה הוא התנהגות שנצפתה; באג מוכר הוא תקלה מסוימת במוצר ובגרסה. מלכודת אחת יכולה לחשוף כמה טיפוסים, ובאג אחד יכול להיחשף בכמה מלכודות. אין לספור תוויות או מופעים כמספר באגים נפרדים.

הגבול הנוכחי הוא ניתוח לא מקוון של ראיות שמורות. אין צורך להפעיל שרת, Docker, Provengo, RESTler או כלי בדיקה אחר; אין ליצור sample ואין לשלוח בקשות חדשות לצורך השלמת השלב הזה. אם דרושה הרצה נוספת כדי להכריע, תעד מה חסר ומהו הניסוי המוצע בנפרד.

## בדיקת סביבה והרצה ראשונה

לפני משיכה מ־Git בדוק את מצב העץ ושמור שינויים קיימים. אין להשתמש ב־reset --hard, clean או stash אוטומטי. אם יש התנגשות, שמור עותק או עבוד בעץ עבודה נפרד; אל תמחק את הסביבה או תוצאות הריצות. שמור את מזהה הקומיט ואת hash הקטלוגים בדוח העבודה.

הפקודות הבאות נועדו ל־PowerShell מתוך הרפו. השתמש בנתיב שאומת בפועל. Python מגרסה 3.9 ומעלה מספיק; המימוש הנמסר משתמש בספרייה הסטנדרטית ואין צורך להתקין חבילות לצורך הנתחן.

```powershell
Set-Location 'C:\work\temp\library-demo'
git status --short
git pull --ff-only origin master
if ($LASTEXITCODE -ne 0) { throw 'Git update failed; preserve local files.' }
git log -1 --oneline
$Python = Join-Path (Get-Location).Path '.venv\Scripts\python.exe'
if (-not (Test-Path -LiteralPath $Python)) { $Python = 'python' }
& $Python --version
if ($LASTEXITCODE -ne 0) { throw 'Python is unavailable.' }
$ReviewRoot = Join-Path (Get-Location).Path ('library\ess-experiment\out\natchan-tse-handoff-' + (Get-Date -Format 'yyyyMMdd-HHmmss-fff'))
```

הבדיקה מפעילה את בדיקות היחידה ואת פקודות הממשק על דוגמאות סינתטיות, ומוודאת שהטיפוסים מפנים לכללים קיימים. היא אינה מאמתת את המתאם של הריצות האמיתיות שלך. סביבת הפיתוח שממנה נמסר הקוד לא כללה PowerShell; לכן בצע גם את בדיקת המעטפת על Windows ושמור את הפלט:

## הכנת רשימת הממצאים הצפויים לפני שינוי הכללים

תחילה אתר את קובצי הריצה, הקוד שהפיק אותם, יומני השער, הגדרות המלכודות, ניתוחי העבר ורשימת הממצאים הידנית. אם זיכרון השיחה אינו זמין, שחזר את המידע מהקבצים; אל תציג השערה כעובדה היסטורית.

לפני התאמת הקטלוג לריצה כלשהי צור expected_manual_findings.json. לכל ממצא שמור מוצר וגרסה, מזהה ידני, מקורות, ריצות רלוונטיות, התופעה שנמצאה, ראיות האישור, בקרות בריאות והסתייגויות. ציין אילו מסקנות נבדקו בקוד או בלוג ואילו היו פרשנות ידנית. הקובץ הוא אמת מידה להשוואה בלבד: אל תטען אותו לתוך מנוע הסיווג כעובדות קלט.

אם קיימות ריצות נוספות שלא שימשו להגדרת הכלל, שמור אותן לבדיקת הכללה. אין לכוונן את הכללים לפי שמות התרחישים, מספרי הדגימות או מזהי הרשומות כדי להבטיח התאמה.

## השלמת הגדרות באגים מוכרים במוצרים

בנפרד מטיפוסים כלליים, השלם את הגדרות הבאגים הספציפיים של Gitea ושל Vikunja. בפרט, בדוק את F01, ‏VIK-F04 ו־C1/C2 ואת דוגמאות מגבלת שם הארגון ו־hex_color אם הן מופיעות במקורות. אל תמציא את משמעותם, את השדות או את הגרסאות לפי השם.

ההגדרות הקיימות של שמות Vikunja הללו הן טיוטות מכוונות. הפעל אותן רק לאחר השלמת גרסאות, פעולות, זהויות ושדות, שרשרת ראיות ותנאים ששוללים התאמה. תנאי שאומר reported_c2_identity_verified אינו מימוש זיהוי; החלף אותו בתנאים שהמתאם יכול לחשב מהראיות המקוריות.

אל תסיק ששתי תקלות הן אותו באג בגלל הודעת שגיאה מנורמלת בלבד. השאר אפשרות לסווג טיפוס בעיה בלי לשייך לבאג מוכר. תעד אם השיוך מבוסס על סימפטום, הפרת כלל עסקי או ראיות שורש תקלה.

## חיבור הראיות לממשקים

שמור על שני צירי הרחבה עצמאיים: ממשק כלי הבדיקה מפרש פורמט ותוצאות מקוריות; ממשק המוצר מפרש פעולות, זהויות, מצב וכללים. אל תכתוב זוג מתאמים חדש לכל צירוף כלי ומוצר.

המתאם ההצהרתי normalize.py יודע להעתיק שדות מפורמט JSON או JSONL; הוא אינו יודע להוכיח זהות, אטומיות או סמיכות. בדוק את הפורמט האמיתי וצור mapping מתאים. אם חסר חישוב סמנטי, כתוב מתאם מוצר שחוזר לראיות המקוריות ומפיק את העובדות, עם הפניות מדויקות למקורות.

אל תשנה fact_basis מ־imported_oracle ל־recomputed רק כדי להפעיל כלל. תוויות אורקל ישנות יישמרו כטענות מקוריות ויושוו לתוצאה שחושבה מחדש. הקוד שמפיק עובדות מאומתות חייב להיות ניתן לבדיקה; כל שדה זהות, סדר או היעדר התערבות צריך להישען על ראיות או על הנחת פרוטוקול מתועדת.

לפני ואחרי חייבים להתייחס לאותו משאב ולזהות הקורא המתאימה, עם סדר ברור ובלי כתיבה מתערבת לא פתורה. אל תחבר ראיות בין resets, תרחישים או epochs. בחר את תמונת הלפני הקרובה המתאימה; זיהינו במאמת היסטורי תמונות צפוי שחלקו מערך משתנה וכללו תוספות מאוחרות, ולכן יש להעדיף snapshots מקוריים.

הצמדת לוג תתבסס ככל האפשר על מזהה בקשה וריצה. ללא מזהה כזה, תעד את העמימות ולא רק התאמת הזמן. היעדר תשובה אינו אוטומטית רעש תשתית; 5xx אינו אוטומטית קריסת תהליך; 403 אינו מוכיח מחיקה; קוד מוצהר אינו תמיד תוצאה נכונה בהקשר.

## הרצה על נתונים קיימים

הקלט הרגיל למוצרים האלה הוא natchan-observations/1. מסלול natchan-analysis/1 שמגיע מ־v002 מיועד כרגע לגשר הספרייה; אין להשתמש בו עבור מוצר אחר או לפרש אפס תצפיות כהצלחה. ודא שמספר הריצות והרשומות בקלט המנורמל מוסבר ומתאים למקור, ושדחיות פענוח ומקורות חסרים אינם נעלמים.

אחרי שיצרת ואימתת mapping מתאים, אלה הפקודות הקיימות. החלף את שני הנתיבים הראשונים בקבצים שאיתרת ויצרת בפועל; אין להריץ נתיב דוגמה כאילו הוא נתון אמיתי:

```powershell
$RawPath = 'REPLACE_WITH_VERIFIED_RAW_JSON_OR_JSONL_PATH'
$MappingPath = 'REPLACE_WITH_VERIFIED_MAPPING_JSON_PATH'
if (-not (Test-Path -LiteralPath $RawPath)) { throw 'Raw input missing.' }
if (-not (Test-Path -LiteralPath $MappingPath)) { throw 'Mapping missing.' }
$NormalizedPath = Join-Path $ReviewRoot 'normalized.json'
& $Python .\tools\natchan-v003\normalize.py `
    --input $RawPath --mapping $MappingPath --output $NormalizedPath
if ($LASTEXITCODE -ne 0) { throw 'Normalization failed.' }
& $Python .\tools\natchan-v003\classifier.py `
    --input $NormalizedPath --output (Join-Path $ReviewRoot 'classification.json')
if ($LASTEXITCODE -ne 0) { throw 'Classification failed.' }
```

אם נדרש מתאם סמנטי ייעודי, הפק באמצעותו את אותו פורמט observations והפעל עליו את אותה פקודת classifier. הוסף את פקודת המתאם המדויקת לדוח ולסקריפט ההרצה שלך; אל תכתוב שהרצה גנרית עבדה אם דילגת על חילוץ העובדות.

עבוד בנפרד לכל מוצר ולכל ריצה, עם מזהי תצפיות ייחודיים. בצבירה של כמה ריצות אל תשכתב את המקורות או הגרסאות ואל תכפיל את אותה ריצה מתוך עותקי ארכיונים. שמור hash של הקלטים והקטלוג. הוצא JSON ודוח Markdown ושמור את הקישור ביניהם.

## בדיקות והשוואה לניתוח הידני

לכל כלל שמופעל נדרשים לפחות מקרה חיובי, מקרה תקין דומה, ראיה חסרה ומקרה עמום או מופרע. בדוק גרסה לא מתאימה, זהות לא מתאימה, כתיבה מתערבת, scope שגוי ותווית מקורית שגויה. הוסף בדיקה לטיפוס המורכב בלי להניח שכל רכיב הוא באג נפרד.

הפעל שוב את שתי חבילות הבדיקות אחרי השינויים. אין לשנות תוצאות צפויות רק כדי להעביר בדיקה: הסבר כל תיקון והצג את מקורו. הפרד בדיקות סינתטיות מאימות על ריצות מקוריות.

הפק parity.csv וגם דוח מסכם. לכל ממצא ידני הצג: מזהה, מוצר וגרסה, מקור הריצה, מלכודת, טיפוסי בעיה צפויים ומחושבים, באג מוכר צפוי ומחושב אם יש, מופעים, ראיות, מצב התאמה וסיבת פער. הצג בנפרד גם ממצאים שהנתחן הפיק ולא הופיעו בניתוח הידני.

המטרה היא התאמה למסקנות שהראיות מצדיקות, ולא התאמה כפויה לכל משפט היסטורי. אם הניתוח הישן טעה או הסתמך על ראיות חסרות, שמור את ההבדל והסבר אותו. אם חסר מימוש, השאר זאת כפער יכולת ולא כאפס באגים. מספר מופעים אינו מספר תקלות, ותדירות בלי מכנה אינה דטרמיניסטיות.

## התוצרים והגדרת הסיום

החזר קטלוגים מעודכנים, טבלת כיסוי מלאה של משפחות TAXONOMY, מתאמים וקוד נדרשים, בדיקות, סקריפט הרצה מקומי מדויק, expected_manual_findings.json, דוחות JSON ו־Markdown, טבלת התאמה ורשימת פערים. ציין קומיט, גרסת Python, hashes ופקודות שבוצעו באמת.

הסבר לכל משפחה האם היא ממומשת, ממתינה לראיות או נותרה כמציין מקום. אין להציג עבודה כמושלמת בגלל שכל השמות מופיעים ב־JSON. אין להציג בדיקה סינתטית כשחזור של באג אמיתי. אין להסתפק במילוי הקטלוג בלי להריץ את הנתחן על הנתונים המקומיים הזמינים.

שמור את השינויים ב־Git בלי למחוק תוצאות מקוריות. עבוד ככל האפשר ברצף; שאל רק כאשר חסר מידע מהותי שאינו ניתן לשחזור מהקבצים. העבר את חוסר הוודאות לדוח במקום להמציא הגדרה.
