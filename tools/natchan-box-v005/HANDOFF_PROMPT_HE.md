# פרומפט למפיק המחקר: תיקון מסלול login בנתחן v005

המקור הוא `geraw/library-demo`, ענף `natchan-box-v005`, נקודת כניסה `tools/natchan-box-v005/natchan.py`. יש להצמיד לקומיט המסירה שנמסר לצד המסמך. הממשק נשאר `natchan-request/1`, המתאם נשאר `toolkit-v1`, ושאר הפלטים וקודי הסיום נשארים כפי שתועדו.

התקלה `ModuleNotFoundError: tse_products` הייתה בנתחן. גרסת ההמשך מסירה את התלות בסדר הייבוא ובודקת את המסלול בתהליך Python נקי. בנוסף היא מזהה מעטפת login, טקסט UTF-16 עם BOM, את `version=v1-login`, את `run_seed` ואת `recorded_http_requests`. בהיעדר גרסה בתוצאת ההרצה, היא משתמשת בגרסה שנמדדה ונשמרה ב־ENV; אין ניחוש מהגרסה הצפויה בקונפיגורציה.

הנתחן משייך `sut_locked_sN.txt` להרצה של אותו seed. זה יומן מסונן ולכן אין להסיק ממנו את סך בקשות השרת או את כלל תשובות ה־500. פסיקות RT-1 נבדקות מתוך ערכי המדידה שנשמרו ובקשת הכתיבה המקורית. ניסיונות חוזרים נשמרים בנפרד ואינם נספרים שוב כבקשות research. השיוך ל־VIK-F01 מחייב התאמה לכללי הקטלוג ולראיות הלוג, ולא מתקבל רק מפני שהמפיק כתב את המזהה הזה.

האימות של recovery מחשב מחדש השוואת גופי prefix וטביעות שנשמרו, עם שיוך למקרה ולסטטוס הבקשה. הוא אינו מציג את `snapshot_restored` כהוכחה עצמאית לשחזור קבצים. תוצאות `negative_checks.pass` ורשימת `findings` של המפיק נשמרות כתוצאות המפיק; הן אינן מועתקות לממצאי הנתחן. החלוקה למקורות ראיה ולפערים מופיעה ב־analysis וב־coverage.

הטיפול במקרי אי־תמיכה שונה באופן ממוקד: פורמט חבילה, גרסת ריצה או סטטוס login לא מוכרים מחזירים exit 3 וסיבה. תקלה פנימית אמיתית ממשיכה להחזיר exit 4. פערי ראיות במבנה נתמך מחזירים PARTIAL עם פירוט, ואינם הופכים את הפלט ל״אפס באגים״.

העדכון הנדרש במפיק הוא הצמדת שילוב הנתחן החדש: repository=`https://github.com/geraw/library-demo`, branch=`natchan-box-v005`, entry=`tools/natchan-box-v005/natchan.py`, adapter=`toolkit-v1`, commit=קומיט המסירה המדויק. עדכן זאת במסלול המפיק הממוספר החדש ובהתאם למדיניות מניפסט התקינות שלו. אל תשכתב תגית מוקפאת, אל תעדכן מניפסט של ניסוי היסטורי בדיעבד ואל תשנה את הראיות המקוריות כדי שיתאימו למפרסר.

השלב הבא הוא ניתוח חוזר של `v1-vikunja-login-20261025-125344.zip`, שכבר נוצר בעבודה. אין צורך בהרצה חדשה מול השרת כדי לבדוק את התיקון. החבילה המקורית לא הייתה זמינה למתחזק; קיימים ב־Git רק הסיכום והמסמך. בדיקות הפורמט בוצעו על fixture קטן ומוצהר, ולכן אין עדיין אישור לעיבוד כל 1369 הבקשות של הריצה המקורית.

הבדיקה על ה־ZIP המקורי צריכה לוודא באופן מכני: קוד נתחן 0 במקום 4, קריאת 1369 רשומות research מבלי להוסיף להן את 14 ניסיונות ה־known-failure, זיהוי 294 רשומות RT ו־seed 1, ושמירת ההבחנה בין חמש תשובות research עם 5xx, ניסיונות חוזרים ושורות לוג הנעילה. אלה מספרי ההתאמה שבמסמך המפיק, לא תנאים לאילוץ ממצאים. מספר השיוכים המאומתים ל־VIK-F01 ייקבע לפי חד־משמעות הראיות, ואין לכפות עליו את מספר השורות בלוג.

הבקשה נשארת באותו מבנה. `examples/vikunja-login.request.json` הוא קובץ דוגמה שאפשר להניח לצד ה־ZIP המקורי; מומלץ להוסיף `evidence.sha256` עם הטביעה שנמדדה בפועל. אין להכניס לתוכה מספרי ממצאים צפויים. הפעל:

```powershell
python .\tools\natchan-box-v005\natchan.py `
    --request 'C:\experiment\analysis-request.json' `
    --output 'C:\experiment\analysis-v005-001'
```

הפלט צריך לכלול את כל תיקיית הניתוח, קובץ הבקשה והטביעות, והבחנה בין סטטוס Provengo, סטטוס המפיק וסטטוס הנתחן. תוצאה PARTIAL צפויה כאשר חסרות ראיות או כשהסמנטיקה אינה מכוסה; היא אינה כישלון של המפרסר. כל ניתוח אנושי נוסף יסומן בנפרד.
