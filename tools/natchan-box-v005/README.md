# Natchan Box v005 — toolkit login-path evidence

Offline Python 3.10+; standard library only; full `geraw/library-demo` checkout required. This release adds the login package described by `weissye/vikunja_study@f3ccb01e5d1ca3c3ef833c456c8239eb1519ccd5:handoff/NATCHAN_PROMPT_login_path_20261025_HE.md`. v001–v004 and the producer remain unchanged. No tests or SUT requests are generated by this analyzer.

## Entry point and interface

```powershell
python -m unittest discover -s .\tools\natchan-box-v005\tests -q
python .\tools\natchan-box-v005\natchan.py --request 'C:\experiment\analysis-request.json' --output 'C:\experiment\analysis-v005-001'
```

The existing `natchan-request/1` and `toolkit-v1` adapter are unchanged. Use a fresh output directory and an immutable original ZIP. For the reported work archive, an example request is in `examples/vikunja-login.request.json`; copy it beside the original ZIP. Its metadata asserts what the evidence must contain; it does not specify expected findings. The optional `Invoke-Natchan-Box-v005.ps1` accepts `-RequestPath` and `-OutputPath`.

The usual outputs remain `result.json` (last/final marker), `findings.json`, `coverage.json`, `provenance.json`, `diagnostics.json`, `report.md`, and successful `analysis.json`. COMPLETE/PARTIAL return 0. Unsupported interface/format returns 3 with an explicit reason; invalid wrapper input returns 2; unexpected engine defects remain 4. No arbitrary engine exception is reclassified as unsupported. Supported but incompletely evidenced semantic checks produce scoped PARTIAL results, not zero findings.

## What was fixed

The generic reader depended on `tse_products` becoming importable as a side effect of a previous Gitea import. In-process tests could mask this. Route/context extraction is now local to the box; an isolated subprocess regression tests both login and an unrelated product. In addition, the old reader did not recognize the login outer ENV file, version/seed/count fields, statuses, control categories or filtered outer server log.

| Input | v005 treatment |
|---|---|
| `ENV_v1_login.txt` | Explicit login package; UTF-8 or BOM-marked UTF-16 |
| `result_v1.json.version = v1-login` | Explicit supported run format |
| `run_seed`, `recorded_http_requests` | Seed and research counts checked against archive/journal |
| Observed version absent in result | Read actual `ENV.sut_version`; never infer it from `sut.json.api.expected_version` |
| `sut_locked_sN.txt` | Exact seed association, original byte source/hash, configured regex count; filtered log scope remains explicit |
| `V1_LOGIN_SAMPLE_COMPLETED` | Recognized selected-model completion, checked against native/live flags and native success marker |
| `V1_LOGIN_TIME_BUDGET_STABLE_PARTIAL` | Supported stable selected prefix; partial coverage remains visible |
| `V1_LOGIN_STATIC_READY` | Static-only evidence, never called a live run |
| `NOT_ACCEPTED` / STOPPED | Retain any real raw prefix and mark the experimental gap |
| Unknown future package/run/status | Structured unsupported reason propagated as exit 3 |

`coverage_v1.json`, when present, must equal the result's coverage copy. Outer and inner result copies must agree. Original hash manifests are still checked. Snapshot adapter, restore verification, recovery/interaction ledger, relationship audit and docker-start journal files are included in the input inventory; their mere presence is not treated as verified SUT behavior.

## Classification and evidence tiers

Research responses remain the HTTP-record count. `known-failure` records describe additional recorded retry attempts; they get separate source-addressable measurements and error classifications and do not inflate research-response counts. Their reported bug IDs do not establish known-bug matches. Transport/authentication/oracle errors are explicit gaps.

Roundtrip observations bind to the immediately preceding matching research exchange (including actor/action/logical ID/method/path and successful status). This permits repeated updates to the same resource without globally ambiguous matching. Only fields qualified as readable and writable by the IR (excluding read-only fields) are promoted to silent-change patterns. Explicit retained sent/stored values are compared, preserving numeric, boolean, request-key/object, array-order and aware date-time semantics. They can yield silent-change patterns with the **producer_readback_values** tier. An absent mismatch entry does not independently prove an unchanged full readback. Full hidden GET bodies remain unavailable.

Filtered database-lock lines are joined to error responses or retry records only with unique method/path/status/time matches within two seconds in both directions. Ambiguity or missing time leaves the join unresolved. A prior successful task creation plus that qualified lock signature may match the existing VIK-F01 catalog conditions; this does not prove a causal timing mechanism. The exact observed `v2.6.0` string is retained. A documented lossless catalog alias to `2.6.0` permits existing version-scoped rules without widening versions; source/effective catalog hashes and transformed entries are recorded.

Recovery records with retained API-prefix bodies are hashed using the producer's published canonical algorithm and compared anew. The negative-write case/status binding is also checked. This verifies the recorded prefix comparison; it does not independently verify filesystem restoration, producer `snapshot_restored` flags, or unobserved state. Contradictory/missing prefix evidence is a gap. Native/result negative-check `pass` and `findings` arrays remain producer summaries, not analyzer findings.

`analysis.json.login_evidence_audit` contains the RT, prefix and log-join audit. Per-run summaries distinguish raw research 5xx, retry-attempt 5xx, partial server-log scope and producer selected-model coverage. Generic patterns and existing catalogs determine findings. Full business semantics of all possible login/recovery oracles are not claimed; `LOGIN_SEMANTIC_COVERAGE_LIMITED` records that scope.
