# פרומפט לשילוב Natchan Box v004 בתהליך המחקר

המשימה היא להפעיל את הנתחן על פלטי המחולל המעודכן, מתוך הראיות הגולמיות בלבד. אין להחליף את הנתחן בניתוח ידני, ואין להוסיף ממצאים צפויים לקלט שלו.

המקור הוא המאגר https://github.com/geraw/library-demo בענף `natchan-box-v004`. נקודת הכניסה היא `tools/natchan-box-v004/natchan.py`. השתמש בקומיט המפורש של המסירה ורשום את `git rev-parse HEAD`. אל תשנה ענפים או תגיות מוקפאים ואל תדרוס פלט קודם. נדרש עותק של המאגר המלא ו־Python 3.10 ומעלה; אין תלות בחבילות חיצוניות.

השינוי בנתחן הוא תמיכה בשדות `atom-snapshots/1` ו־`div-evidence/1` שהוספו במפיק החל מהקומיט `d990657a2470d4dbf368d4d5eb592749a292f6ff` במאגר `weissye/vikunja_study`. הנתחן לא שינה את המחולל ולא ביצע בקשות לשרת.

האימות החדש מחשב את שדות האטומיות, שינויי הלוואי והפסיקה מתוך הבקשה ותמונות המצב, וקושר אותם לבקשה גולמית יחידה. בהשוואות יצירה–עדכון הוא מאמת את שני העותקים מול רשומות הבקשות המקוריות, מחלץ שדה מה־IR ומחשב את מחלקות התשובה. כששני הצדדים הצליחו, הוא בודק את ההצבעות למדידות הקריאה החוזרת; אלו אינן גופי קריאה מלאים, ולכן מסומנות כהשוואת מדידות בלבד. אי־התאמה למפיק נשמרת כסתירה ואינה מוסתרת.

ההרצה תשתלב אחרי אריזת הראיות ובדיקת ההסתרה. יש להריץ את הנתחן גם על קידומת של ניסוי שנעצר, אם נשמרו בה ראיות. כשל ניסוי, כשל כלי השוואה וסטטוס ניתוח הם שלושה דברים שונים. אין לסמן ניסוי כהצלחה משום שהנתחן הצליח לעבד את הקבצים.

הקלט הוא בקשת `natchan-request/1` וה־ZIP המקורי, ללא שינוי. התצורה הקודמת והמתאם `toolkit-v1` נשארים תקפים. נתיבים יחסיים נפתרים ביחס לתיקיית קובץ הבקשה. אין שדה seed בבקשת המעטפת; הוא מגיע מהראיות. במקרה של חבילה עם כמה כלים, השתמש ב־`mixed` כמפורט ב־README של v002. הדוגמה הבאה היא עבור מודל או קמפיין יחיד של Gitea:

```json
{
  "schema_version": "natchan-request/1",
  "run": {"id": "home-model-evidence-001", "tool": "provengo", "product": "gitea", "product_version": "28.1.0"},
  "evidence": {"adapter": "toolkit-v1", "archive": "review_v1_s1.zip", "sha256": "REPLACE_WITH_ACTUAL_LOWERCASE_SHA256"}
}
```

הגרסה והמערכת בבקשה הן טענות שייבדקו מול המטא־דאטה, ולא דרך להשלים ראיה חסרה. אם החבילה מכילה `sut.json` אין צורך להמציא הגדרות מערכת. בחבילה ישנה בלי הקובץ אפשר להשתמש בהגדרות `sut_config` או `toolkit_repo` לפי README; אין לשנות את ה־ZIP לצורך כך.

הפקודות מתוך שורש עותק הנתחן הן:

```powershell
python -m unittest discover -s .\tools\natchan-box-v004\tests -v
if ($LASTEXITCODE -ne 0) { throw 'Natchan tests failed.' }

python .\tools\natchan-box-v004\natchan.py `
    --request 'D:\experiment\analysis-request.json' `
    --output 'D:\experiment\analysis-v004-001'
if ($LASTEXITCODE -ne 0) { throw 'Analysis failed; inspect diagnostics.json.' }

Get-Content -LiteralPath 'D:\experiment\analysis-v004-001\result.json' -Raw
```

הפלט המחייב הוא `result.json`, שנכתב אחרון. קודי COMPLETE ו־PARTIAL מחזירים 0; PARTIAL עדיין כולל פערים. כשל קלט מחזיר 2, ממשק לא נתמך 3, וכשל מנוע 4. ממצאים מופיעים ב־`findings.json`, הכיסוי והפערים ב־`coverage.json`, המקורות והטביעות ב־`provenance.json`, ופירוט החישוב ב־`analysis.json`. הקובץ `report.md` הוא תצוגה שהנתחן מפיק. יש לשמור את כל תיקיית הפלט ואת קובץ הבקשה לצד הניסוי, בלי להעביר סודות לתיקייה המשותפת.

הבדיקה הבאה לקבלת הגרסה היא הרצה ביתית אמיתית של המפיק המעודכן עם ה־JAR המוקפא, ואחריה ניתוח ה־ZIP שנוצר. אם מתבצעת כבר הרצה כזו אין ליצור ריצה נוספת רק כדי לנתח. יש לבדוק בפועל ששדות התוספת נמצאים ביומן ולהעביר את טביעת ה־JAR שנמדדה ואת סטטוס הניסוי. בדוגמאות הענן שסופקו נעשה שימוש ב־harness; אין להציג אותן כאישור של תזמון Provengo, גם אם ביומן מופיעה שורת SUCCESS.

ההשוואה שנבדקה כאן היא:

|---|---:|---:|
| בקשות research | 431 | 431 |
| תשובות 5xx | 11 | 11 |
| פערי ראיות ATOM ו־DIV | 47 | 4 |
| בדיקות אטומיות שאומתו מתמונות | 0 | 8 |

הפירוט הוא שש שמירות חלקיות ושני ביטולים; מתוך 35 זוגות DIV יש חמש השוואות עם הבדל במחלקת התשובה ושלושים ללא הבדל. עשרים ואחת מההשוואות נעזרות במדידות קריאה חוזרת ואינן אימות עצמאי של גופי הקריאות. אין לסכם תוויות חופפות למספר באגים.

הפערים שנותרו בדוגמה הם רשומות 605–608: שלושה זוגות של הפניות שנשלחו עם מזהים שונים, וזוג נוסף עם אותו מזהה אך בהקשר repository שונה. המפיק מדווח על שלושה הבדלים במחלקות תשובה בקבוצה הזו. הנתחן משאיר אותם כהשוואות לא כשירות לפי כללי ההקשר שנבדקו, ולא טוען שאין שם התנהגות מעניינת. כדי לקבל השוואה סמנטית בין מזהים שונים נדרש בעתיד כלל שקילות מפורש עם ראיות לבעלות/מחיקה/תחום; אין לרכך את הכלל רק כדי לקבל את המספר שמונה.

המגבלות הנוספות נשמרות: מקור מצב לפני מסוג `last_2xx_representation` אינו קריאה טרייה; אין הוכחה להיעדר כותבים אחרים; תמונת לפני חסרה או קריאה חוזרת לא תקינה נשארות פער; יצירה ומחיקה אינן מאומתות על ידי מאמת תמונות העדכון החדש. תמיכה בפורמט גנרי אינה הבטחה להבנה אוטומטית של כל מדיניות עסקית במערכת חדשה.

המסירה לאחר ההרצה צריכה לכלול קומיטי מפיק ונתחן, בקשה, SHA256 של הקלט, סטטוס הניסוי, סטטוס הנתחן וקוד הסיום, כל הפלטים, טבלת שינויים בקטגוריות ובפערים ורשימת המגבלות שנותרו. ניתוח אנושי, אם נעשה, יסומן בנפרד. אל תכפה על ריצה חדשה את ספירות דוגמת הענן.
