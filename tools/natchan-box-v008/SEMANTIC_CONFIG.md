# Semantic metadata interface

`natchan-story-semantics/1` separates product data from generic rule code. It is analysis configuration, not observed server state or a list of expected bugs. Profiles do not contain expected response counts, seeds, bug IDs or prerecorded response values.

## Generate a profile

Use the original OpenAPI bytes and producer story IR containing `entities` and `stories`:

```powershell
python .\tools\natchan-box-v008\derive_story_semantics.py --contract C:\experiment\contract.json --derived-stories C:\experiment\stories-product.json --product product --output C:\experiment\story-semantics.json
```

No network, Java, Provengo or SUT is invoked. The profile records contract and IR SHA256 hashes. Relations/projections come from the contract-derived IR; operator meanings are parsed from descriptions such as `` `r` - Replace ``. Missing meanings are not guessed from enum order. Inspect the generated hypotheses before a frozen evaluation; deriving metadata is not a substitute for defining the intended oracle.

The bundled wger profile explicitly uses `--display-rounding-steps 0.5,1,1.25,2.5` to preserve the producer's existing display-quantization tolerance. Those steps are a recorded tolerance policy, **not a guarantee in OpenAPI**. A discrepancy compatible with those nearest-display steps remains an observation. Other discrepancies under unspecified rounding remain candidates with an uncertainty gap.

## Select the profile

An immutable package may contain `story-semantics.json`. To analyze existing packages without changing their bytes, add:

```json
"configuration": {"story_semantics": "story-semantics.json"}
```

Paths are relative to the request file. An external profile and an embedded one cannot both be selected. If neither is supplied, a bundled product profile may be used. Its `product` and `contract_sha256` must match the run. Profiles cannot supply an observed SUT version. A contract hash conflict is a coverage gap; a contradictory product is invalid input. The profile's original bytes/hash enter provenance.

## Fields

| Field | Purpose |
|---|---|
| `schema_version` | Exactly `natchan-story-semantics/1` |
| `product` | Canonical product identifier, matching evidence |
| `contract_sha256` | Binding to the exact OpenAPI bytes reported by the run |
| `entities` | Named entity data: create method/path, detail template, ID field and reference fields/targets/shapes |
| `projections` | Read route template, owner, root array flag and declared child places/parent places/reference fields |
| `arithmetic` | Config entity, parent reference, operator/iteration/value/mode fields and meanings, computed view path, item projection and output field |
| `rounding` | Explicit arithmetic policy: `unspecified`, `none`, `floor` or `half_up`; positive `quantum` when quantizing after every operation; optional tolerated nearest-display `display_steps` |
| `derivation_sources` | Hashes of the source contract and story IR |

Projection paths support only `$`, `$[]`, `.field` and `[]`, for example `$.groups[].items[]`; no executable expressions or arbitrary JSONPath filters. Entity and parent identities are scoped by declared routes/places, not by a globally matching integer. Grouped array roots and the producer's alternate first-level array shape are qualified by the actual positive preimage.

## Adding known bug names

Generic detection does not need a bug ID. `story_profiles.json` optionally links recomputed facts and paths to known behavior-signature candidates. This must remain separate from semantic metadata and version-qualified known-bug catalogs. Adding a new candidate after seeing a behavior is retrospective classification; it cannot be reported as prospective independent bug discovery.

## Unsupported or incomplete evidence

A new product with no profile still gets supported raw/generic analysis and an explicit semantic-profile gap. Unsupported profile schema/policy returns exit 3. Invalid supported metadata returns exit 2. Missing controls, ambiguous attempts, conflicting contract bindings and uncertain rounding remain gaps; no cached producer verdict supplies the missing proof. Full business semantics may require additional generic rules beyond those in this release.

## v008 shared-judge extensions

The same configuration is used for stories and raw baseline HTTP. Optional extensions are currently **reviewed explicit metadata**, not all automatically generated by `derive_story_semantics.py`. Derive the base from permitted contract/IR sources, review hypotheses, then freeze before prospective evidence. Never encode bug IDs, expected failures or observed anomaly values in this file.

| Extension | Data and controls |
|---|---|
| `api_base_path` | Optional prefix stripped on an exact boundary in raw/model captures; original `captured_path` retained |
| Entity `detail_key_parameter` | Route parameter for the entity ID when its name differs from `id_field` |
| Entity `create_result_items` | Path to full newly created objects inside a wrapper, e.g. `$.createdItems[]` |
| Entity `scalar_create_key` | A scalar create response is the detail key (e.g. recipe slug); later full bodies still required for state comparisons |
| `detail_route_entities` | Explicit route-template to entity mapping for legitimately ambiguous detail routes; no ID-based guessing |
| `contributions` | Method/action/source/container templates; URL parameter bindings; source stable ID field; scale field; quantity; source/container item projections; per-key alternative scalar accessors; sign ±1 |
| `copies` | Copy method/action/source templates; source URL bindings; identity-items/reference-items projections and shared internal-key field |
| `aggregates` | Child/parent entities, changed reference field, numeric child/parent view routes and fields. Requires observed additive create control and old/new preimages |
| `log_correlation` | Optional JSON/text server-log reader, opt-in unique time joins and server-reported error signature regexes; see HTTP_EVIDENCE.md |

Contribution `source_keys` and `container_keys` are parallel arrays: each component is a list of alternative accessors, such as `["food.id","foodId"]`. Present alternatives must agree and resolve to scalar IDs. Totals are compared per key using Decimal (absolute comparison tolerance 1e-9). Missing collections/quantities/keys are unknown; an absent array is not assumed empty. Source/container preimages must be current, accepted actions must bind the right resources, and intervening writes block attribution. A zero-net sequence is checked separately as a roundtrip.

Copy analysis first checks that the source's internal references resolve inside the source. A different observed copy identity is required. Both the response and its first qualified readback may expose the same inconsistency; they are separate occurrences of a possible single bug. Empty/missing projections are not credited as correct copies. No concurrent/intervening mutation is attributed to the copy action.

Configured aggregate moves use the existing numeric tolerance `0.011*(n+1) + 0.0001*abs(expected)`, with n=1 here. This is a retrospective comparison policy inherited from the aggregate oracle, not an OpenAPI business guarantee. The additive creation delta must first be observed; the child creation, old/new parents, acknowledged move and numeric views must be bound. Product-specific rounding or nonadditive semantics may require another declared rule/policy.

Reference audits currently qualify scalar/array/object relationship fields observable on the directly read resource. Nested reference shapes present in an IR/profile are not a claim of complete nested-precondition auditing. Missing target metadata, snapshots or post-read fields cannot establish cleared/dangling state. Full product business coverage is never implied by the existence of a profile.

The Mealie profile's `contract_materialization: "not_retained"` explicitly records that the original OpenAPI bytes are absent from this corpus. Its binding is the exact hash recorded in the retained runs, with IR/source provenance and reviewed route/key data. Use new original contract bytes and a separately frozen reviewed profile for another contract revision; do not silently substitute a current live contract.
