הנחיות למתחזק תהליך המחקר — שילוב נתחן v006

המטרה: לנתח בסוף כל הרצה את חבילת הראיות המקורית באמצעות קופסת הנתחן, לרבות חבילות stories-dev. אין לשנות ניסויים, סיפורים, הגדרות חיפוש, תוצאות או תגיות קפואות כדי להתאים למנתח.

המקור: geraw/library-demo, הענף natchan-box-v006, התיקייה tools/natchan-box-v006. לפני שילוב קבע את ה-commit המדויק של הענף ושמור אותו בתצורה ממוספרת חדשה ובפרובננס. הבסיס הקודם הוא 350cf773652dc2bc52de0617bb6e6f385016c6e7. הקובץ SHA256.json מגדיר את קובצי הקופסה; נדרש checkout מלא של הריפו משום שקיימות תלויות במנתחים קודמים.

השינויים: נוסף קורא ל-result_stories.json ול-review_stories.zip; נשמר השם toolkit-v1 של המתאם כדי לא לשבור את ממשק הבקשה. נוספו כללי ניתוח כלליים להפניות שנמחקו, כתיבה עם הפניה ישנה, 500 על משאב חסר וסכום לאחר העברה. נוספה השוואה חוזרת של מדידות CONTRIBUTION ושל INTRA-REF מתוך STORY_CHECK, ברמת ראיה חלשה יותר. פורמט בלתי נתמך מחזיר כעת 3 במקום התקלה 4 שתוארה במסירה. סתירה מזוהה בראיות הסיפורים מחזירה 2. תקלת קוד בלתי צפויה נשארת 4.

התהליך הנדרש:

1. הרץ את בדיקות הקופסה ב-checkout המוצמד:

```powershell
python -m unittest discover -s .\tools\natchan-box-v006\tests -q
if ($LASTEXITCODE -ne 0) { throw 'Analyzer tests failed.' }
```

2. לאחר הפקת חבילת ההרצה, שמור את ה-ZIP המקורי ללא שינוי. צור לידו analysis-request.json. זהו קלט מנותב, לא רשימת ממצאים צפויים:

```json
{
  "schema_version": "natchan-request/1",
  "run": {"id": "mealie-stories-run", "tool": "provengo", "product": "mealie", "product_version": "unknown"},
  "evidence": {"adapter": "toolkit-v1", "archive": "stories.zip"}
}
```

ההתאמה: החלף id ושם ZIP בערכים האמיתיים. עבור wger השתמש product=wger. עבור תווית המפיק mealie-pg השתמש במוצר הקנוני mealie; התווית המקורית נשמרת בביקורת. גרסת מוצר בבקשה אינה תחליף לגרסה שנצפתה ונשמרה בתוצאות. בחבילות הקיימות חסרה גרסה כזאת ולכן unknown הוא הערך הנכון.

3. הפעל בתהליך Python, עם תיקיית פלט חדשה, ושמור מיד את הקוד שהחזיר:

```powershell
python .\tools\natchan-box-v006\natchan.py --request $requestPath --output $analysisOutput
$analysisExit = $LASTEXITCODE
```

המשמעות: 0 הוא עיבוד שהושלם, עם סטטוס COMPLETE או PARTIAL. הוא אינו מעיד על היעדר באגים. קוד 2 הוא קלט פסול, 3 הוא פורמט שאינו נתמך, 4 הוא תקלה פנימית. שמור את הקוד, הסטטוס והסיבה בסטטוס התהליך, ואל תסמן הרצת SUT שנכשלה כהצלחה בגלל שהניתוח הצליח, או להפך. אל תדלג על כשל בשקט. שמור גם את stderr במקרה שאין תיקיית פלט.

4. צרף לתוצר המחקר result.json, findings.json, coverage.json, provenance.json, diagnostics.json ו-report.md; שמור analysis.json המלא לבדיקה. קובצי הפלט עלולים לכלול נתיבים ונתונים מקומיים. בצע את מנגנון ההסתרה ובדיקת הדליפה של המפיק לפני שיתוף, ושמור את העותק המקורי הפרטי ואת מיפוי ההסתרה לפי נוהל המחקר.

5. בדוק קודם את ארבע חבילות הסיפורים המקוריות הקיימות מ-26 באוקטובר, בלי להריץ שוב את המערכות. הפלט הצפוי מבחינת התמיכה הוא exit 0 עם PARTIAL, ולא exit 4. השווה ממצאים לפי סוג ומקור; אין לכפות ספירות על חבילה מלאה על בסיס תת-הקבוצה ששמורה ב-Git. בדוק גם את חבילת login המקורית ואת ספירות 1369/14/294/5 בנפרד. acceptance המקורי שלה דווח עבור v005, ולא בוצע מחדש כאן על ה-ZIP המלא.

ההפרדה המחקרית: M-D1, M-D2, M-C1 ו-W-F2 הם מועמדים לפי חתימת התנהגות בשדה known_bug_candidates. הם אינם known_bug_occurrences מאושרי גרסה, משום שגרסת השרת חסרה. בריצה המוקדמת של Mealie יש רק מדידות שמורות של contribution ושל copy, ללא יומן HTTP מלא בתת-הקבוצה שבמאגר. לכן אין להציג אותה כאישור עצמאי מלא מתוך HTTP. אין לסכום תגיות חופפות כאילו הן באגים שונים.

השיפור הנדרש במפיק להבא: שמור observed sut_version ממקור השרת, seed כשקיים, יומן HTTP מלא לרבות גופי הקריאות של האורקלים, המיפוי מהפעולה לבדיקה וקובץ hash manifest. שמור בבירור את סוג הריצה provengo מול harness. אלה שינויים בראיות המופקות, לא סיבה לשכתב בדיעבד תוצאות או להשלים ערכים מה-NOTE. תיעוד sut.json או expected_version לבדם אינם הוכחה לגרסה שנבדקה.

המסירה: השילוב האוטומטי בקוד המפיק לא בוצע על ידי גרסת הנתחן הזאת. יישם אותו במסלול ממוספר חדש, בדוק בדיקות כשל מכוונות לקודים 2/3/4, והחזר commit, פקודת ההרצה, קודי היציאה, ספירות, פערי כיסוי וקישור לתוצרים שעברו הסתרה. התנהגות שהנתחן עדיין אינו תומך בה תישאר פער מפורש, ולא תשויך ידנית לפלט האוטומטי.
